# BEHAVIOR 评测输入、控制和预算

依据固定 v3.9.3 的 `docs/challenge/evaluation.md` 与 https://behavior.stanford.edu/challenge/evaluation.html（2026-09-26 核对）。

## 策略知道什么

2026 challenge 输入是机器人机载 RGB、深度、本体感知；允许使用 BDDL 任务定义。不能直接读取物体真值状态/位置、机器人全局位姿、全场景点云、真值分割等仿真器特权信息。策略可用允许的观测做 SLAM、视觉定位、地图记忆、规划和 LLM 推理。

“全局理解”需要区分：任务的完整目标可提供；从探索得到的房间/路线记忆可维护；仿真器直接导出的全屋真值地图不能当作标准评测输入。用于研究的特权模式应单独命名、保存配置，不和该轨道成绩混报。

## 策略怎么知道如何控制

这与知道全局场景不是同一件事。World 工具提供明确的动作契约：

- move_base：机器人局部 +x 前、+y 左，速度 m/s；正偏航逆时针，rad/s；上限0.3m/s与0.5rad/s。每次调用结束后新调用未指定的速度为0。
- move_robot：在同一段 1..30 个环境步里同时指定双臂绝对位姿、底盘速度、双夹爪开度和可用的躯干关节目标；步数只计一次。字段、单位和限位与下面的单项工具相同。夹爪与运动同时开始，不等待手臂到达；需要先接近再闭合时拆成两次调用。底盘运动时末端目标随机器人根坐标系移动。单独的工具调用仍串行执行。
- move_arms：机器人 articulation-root 坐标系中的绝对末端位置（米）与 XYZW 四元数，由外部配置的 IK 控制器求关节动作。不是世界坐标，也不是保证避障的路径规划。
- set_grippers：0闭合、1张开；目标会保持。是否抓住必须从反馈判断。
- move_torso：按本体感知字段顺序指定躯干关节位置，单位弧度，按实际关节限位校验。
- 每个动作持续1–30个30Hz控制步；执行后回传机载图像、深度可视化、本体状态与执行反馈。

官方支持自定义 OmniGibson 机器人/控制器配置，因此 IK 并非规则上天然禁止；但 World 的21维 IK 接口与原版23维关节控制必须分别记录。Isaac 6外部兼容运行也不能自动视为官方5.1镜像验证结果。

当前实现具备传感器观测、动作接口、Codex对话记忆、4 history/interval2、完整事件与连续视频；**尚未实现完整 SLAM、持久空间地图、视觉目标定位、抓取规划和导航模块**。提示词要求维护地标/路线/携带物/未完成目标，只是对话规划辅助，不等于这些模块已实现。增加步数不保证任务成功。

官方还提供每任务200条人类示范，baseline 文档给出 π0.5 与 GR00T N1.7 的微调/评测流程。这些策略可从训练数据学习操作与任务经验；当前 World 接线没有使用这些示范训练 Codex，不能把接口跑通视为具有同等操作能力。参考：[官方 baselines](https://behavior.stanford.edu/challenge/baselines.html)。

## 官方怎么打分

Q衡量episode结束时满足的目标BDDL谓词比例；还记录完整任务成功与仿真时间、底盘路程、末端位移等效率指标。环境判分，模型不能自报成功。

正式自评使用100个任务、各任务public index 0–9，每实例一次，默认预算为平均人类示范长度的1.5倍。index10–19用于开发；不得挑选每实例多次运行中的最佳结果冒充正式成绩。

## 本次5000步开发运行

任务carrying_in_groceries，public index10 / instance311，预算5000仿真步，最多1000次有效动作调用，策略墙钟7200秒、容器墙钟9000秒。输出：`World/var/runs/docker/behavior_1k/groceries-codex-5000steps-01/`。

5000/30约166.7秒仿真时间，模型思考时仿真暂停。完整任务的原始默认预算为int(14274.805×1.5)=21412步，约713.7秒。因此5000步是人为缩短的开发预算，不是官方完整预算。沿用原版超时计数逻辑，终止记录可能为5001步，不修改上游以隐藏这个差异。

prompt显示设定步数与剩余预算；完整轨迹写入 `rollout-000/events/`，自动生成 `events/no-images/`。当前策略不提供主动放弃工具，普通对话结束后会在同一线程继续尝试。最终查看官方 `results.json`、视频和 `episode.json` 中策略停止原因，区分环境结束、硬性预算耗尽、中断和基础设施错误；历史日志可能仍有 `give_up`。
