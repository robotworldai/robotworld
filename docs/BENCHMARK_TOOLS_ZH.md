# World 各 benchmark 工具清单与中文说明

核对日期：2026-09-28。根据当前适配器实际注册的动态工具整理；英文工具名保持原样，说明翻译为中文。本文不修改模型实际接收的工具 schema。

## 阅读口径

- 以下统计机器人的环境工具，不包含 Codex 自带的 Shell、文件操作等通用工具。
- `coding_control` 是否提供取决于运行配置；纯动作对照实验会将它关闭。具体某次运行以其 `prompt.json` 中的有效工具清单为准。
- 工具执行成功不等于任务成功；评测器决定任务结果，保留原生失败和超时规则。
- `steps` 是环境控制步数，不是 LLM 调用次数或物理子步数。不同 benchmark 的控制频率不同。
- `coding_control` 让模型编写的程序逐控制步读取新反馈并输出动作，不是每一步重新调用模型。它不能绕过工具直接修改仿真场景、重置环境或宣布成功。
- T04、T15 是已有接口但环境初始化仍阻塞；原 T05 1v1 仍缺完整对手策略。工具定义存在不代表任务已实测跑通。

## 1. RoboDojo：1 个工具

| 工具 | 中文说明 |
|---|---|
| `move_eef` | 将左臂、右臂抓取点移动到世界坐标系中的绝对目标。位置单位为米；姿态是相对垂直向下抓取姿态定义的角度，单位为度。未指定维度保持当前观测值。双臂可沿时间对齐的路径同时运动。同一次调用指定夹爪时，到达目标后才执行夹爪动作。运动按固定速度执行，预计超过 10 秒需要拆分。 |

夹爪包含在此工具中，没有独立夹爪工具。姿态零值表示工具轴指向世界 -Z；pitch、roll、yaw 分别按接口定义绕世界 X、Y、Z 轴旋转，不能直接套用其他 benchmark 的欧拉角约定。各维度名称和范围由运行时 schema 给出。

来源：[eef_executor.py](../environment/benchmarks/robodojo/eef_executor.py)

## 2. BEHAVIOR-1K：当前 R1Pro 配置 5 个工具

| 工具 | 中文说明 |
|---|---|
| `move_arms` | 使用绝对位姿 IK 移动单臂或双臂。位置相对机器人根坐标系，单位米；姿态为 XYZW 四元数。底盘不动，未指定手臂保持观测到的位姿，夹爪目标持续保持。 |
| `move_base` | 控制全向底盘局部速度：+X 前进、+Y 向左、正偏航逆时针。平移单位 m/s，转向单位 rad/s。手臂保持相对机器人根部的末端目标，夹爪目标保持；速度仅在本动作段内生效。 |
| `set_grippers` | 设置左右夹爪开度：0 关闭、1 打开。末端保持观测到的机器人相对位姿，底盘停止。夹爪目标持续保持，仍需观测确认是否抓住物体。 |
| `move_torso` | 设置躯干关节绝对角度，单位弧度；顺序和限位来自当前配置。手臂使用 IK 保持机器人相对末端目标。仅在配置存在躯干控制器时提供。 |
| `move_robot` | 在同一个原生动作里同时控制双臂、底盘、夹爪及可用的躯干。各部分共享控制步计数。夹爪从运动开始就执行；底盘移动时，手臂目标随机器人根部移动，不是固定世界坐标。 |

每次运动执行 1–30 个控制步，30 Hz。底盘平移输入范围分别为 ±0.3 m/s，偏航为 ±0.5 rad/s。未指定底盘速度为零；未指定末端维度、躯干目标保持测量值，夹爪目标持续保持。IK 不保证跟踪精度或无碰撞路径；需要同步控制时使用 `move_robot`，不是并行调用多个运动工具。

来源：[control.py](../environment/benchmarks/behavior_1k/control.py)

## 3. RoboCasa：5 个工具

| 工具 | 中文说明 |
|---|---|
| `move_eef` | 输入机器人底座坐标系下的末端六维归一化 OSC 增量 `[dx,dy,dz,rx,ry,rz]`。范围 [-1,1]，各平移和旋转通道分别映射到最多 0.05 m、0.5 rad 每步。不是绝对目标；重复执行会累积增量。 |
| `move_base` | 输入底盘平移和转向的三个归一化控制量，范围 [-1,1]，不是直接填写 m/s。启用底盘跟随模式，夹爪目标保持。 |
| `move_torso` | 输入躯干关节的归一化位置增量，范围 [-1,1]，不是绝对高度。使用底盘跟随模式，手臂增量为零。 |
| `set_gripper` | 设置夹爪：1 关闭、0 打开。目标持续保持，不请求手臂、底盘或躯干运动。 |
| `move_robot` | 同时控制末端、底盘、躯干和夹爪。`control_mode=0` 从实际到达位姿更新手臂目标；`1` 从期望位姿更新，以配合底盘跟随。 |

每次执行 1–30 步。`move_eef` 未指定的底盘和躯干运动为零。这个工具与 RoboDojo 同名，但动作含义不同。

来源：[control.py](../environment/benchmarks/robocasa/control.py)

## 4. RoboLab：每种控制配置 3 个工具

| 工具 | 中文说明 |
|---|---|
| `move_joints` 或 `move_eef` | 关节模式提供 `move_joints`：输入 7 个绝对关节角，单位弧度。IK 模式提供 `move_eef`：绝对模式使用机器人根坐标系下的 base_link 位置和 WXYZ 四元数；相对模式输入根坐标轴下六维位姿增量，旋转为旋转向量，原生缩放系数 0.5，重复步会累积。 |
| `set_gripper` | 设置夹爪：0 打开、1 关闭，目标持续保持。 |
| `move_robot` | 在同一个动作中同时控制机械臂和夹爪，夹爪立即开始执行；必要时将接近和闭合拆开。 |

每次执行 1–30 步，15 Hz。未指定绝对位姿或关节目标保持测量值，未指定相对增量为零。该固定底座 DROID 配置没有底盘、躯干或头部控制器；IK 不规划无碰撞路径。

来源：[control.py](../environment/benchmarks/robolab/control.py)

## 5. HumanoidSoccer / T12：每种模式 2 个工具

| 模式 | 工具 | 中文说明 |
|---|---|---|
| 直接控制 | `move_joints` | 通过原生 PD 控制器设置 G1 各命名关节的绝对目标角度，单位弧度，各关节同时执行。未指定关节保持调用开始时的测量角度。可选踝关节平衡辅助会明确记录，它不是行走或碰撞规划器。 |
| 混合控制 | `review_action` | 接受原 PAiD 策略动作，或者给指定关节增加 ±0.25 rad 内的目标偏移。原策略每步重新预测，同一偏移应用到动作段内每一步的新预测上。这是动作段级监督，不是逐个审阅尚未生成的未来动作。 |
| 两种模式都有 | `coding_control` | 编写 `control(obs, memory)`，每个 0.02 秒控制步读取新数值反馈并输出动作。直接模式返回关节绝对目标；混合模式返回接受或修改策略动作。单次最多 500 步。 |

普通运动工具单次执行 1–50 步，50 Hz。代码返回 `{"done": true}` 只停止当前程序段并回传观测，不宣布任务成功。程序记忆只在本次调用内持续；原 PD 和可选平衡辅助仍以 500 Hz 运行。没有自动提供行走或踢球规划器。

来源：[control.py](../environment/benchmarks/humanoid_soccer/control.py)

## 6. WheeledLab / T06 及自建驾驶题：默认 3 个工具

| 工具 | 中文说明 |
|---|---|
| `observe` | 读取当前观测，不推进物理仿真。车载观测模式提供前向 RGB、轮速/转向编码器和 IMU，不提供隐藏地图、世界位姿、检查点进度或闸门通行空间答案。 |
| `drive` | 同时输入归一化速度和转向 `[speed, steering]`，范围 [-1,1]，执行 1–50 步。速度目标按 `3×speed m/s` 换算，转向参数按 `0.488×steering rad` 换算后经过原生转向机构。目标不保证实际位移或即时制动。 |
| `coding_control` | 编写逐步反馈程序，每个控制步更新速度和转向，单次最多 250 步。车载模式只使用允许的车载像素、编码器和 IMU；需要自行从观测判断道路和障碍。 |

原生漂移任务不支持倒车，负速度输入被截为零；支持倒车的停车题使用有符号速度，并提供后摄像头信息。车载代码控制的前向图像为 48×27 RGB。没有附带停车规划器。工具内记忆只在当前调用内持续。

来源：[control.py](../environment/benchmarks/wheeledlab/control.py)

## 7. AI-CPS：通常 3 个工具，ID34 多 1 个

| 工具 | 中文说明 |
|---|---|
| `observe` | 读取当前状态与相机历史，不推进物理仿真。 |
| `move_joints` | 同时控制 7 个机械臂关节的归一化增量。每步把 `输入×0.125 rad` 加到上一目标上，再做关节限位处理；保留原生噪声。零输入保持加噪前的上一目标，不是当前测量角度。手指由任务控制，没有 EEF 规划器。单次 1–50 步。 |
| `coding_control` | 每个约 1/60 秒控制步读取新数值状态，计算下一步 7 维归一化关节增量；单次最多 300 步。程序记忆在当前调用内持续，非法代码或动作会停止程序。 |
| `cancel_action`，仅 ID34 | 确认真实接触异常造成的中断，丢弃旧动作段，进入本回合持续的降级控制。后续含噪关节目标每步变化限制为 0.00625 rad；实际速度和惯性仍由物理系统决定。此调用不推进物理，也不表示恢复成功。 |

ID22、23、24 默认使用前三个；关闭代码控制后只保留观测和关节工具。ID34 额外保留接触异常取消工具。

来源：[control.py](../environment/benchmarks/ai_cps/control.py)

## 8. 其余 T 系列：共用工具名称，使用各自原生动作

| 工具 | 中文说明 |
|---|---|
| `observe` | 读取当前原生策略观测，不推进物理仿真。 |
| `apply_action` | 同时执行完整原生动作向量，持续 1–50 个控制步。重复的是同一动作，不自动插值轨迹。动作维度、顺序、单位、增益、零值含义和边界以该任务运行时控制说明为准，不能统一理解为力度百分比。 |
| `coding_control` | 编写单个 `control(obs, memory)` 函数，每个原生控制步读取新观测，返回 `{"action": [...]}` 或 `{"done": true}`。单次最多 250 步，只能使用提供的观测和 JSON 记忆，不能访问模拟器。这个共享解释器不支持额外辅助函数或嵌套函数定义。 |

默认是上述 3 个工具；关闭代码控制时是前 2 个。

| Benchmark / 任务 | `apply_action` 的具体控制对象 | 接入边界 |
|---|---|---|
| SteadyTray / T01 | 人形机器人原生关节动作，控制身体和持托盘姿态 | 具体关节顺序和缩放来自运行时 |
| TTRL / T02 | 乒乓机器人原生关节目标偏移 | 不是直接指定球拍轨迹 |
| ReflexBench / T03 | 末端绝对位置、WXYZ 姿态和夹爪，共 8 维 | 位置相对机器人根坐标系，原生 IK 解算机械臂 |
| aerial_balance / T04 | 期望竖直速度增量 | 接口已写，初始化仍阻塞；保留原接口延迟 |
| VolleyBots / T05-single | Iris 的 4 个原始旋翼输入 | 官方单机颠球已实测；原 T05 1v1 仍缺完整对手策略 |
| Wheel-Legged-Lab / T07、T08 | 左右虚拟腿角度、腿长、轮速，共 6 维 | 原生 VMC 转成电机力矩，不是 6 个原始关节角 |
| wheeled_quadruped / T09 | 原生腿部关节位置和轮速 | 后两轮支撑平衡 |
| Go2 Push / T10 | Go2 原生关节目标 | 未附带训练好的步态策略 |
| agilex `robot_lab` / T11 | A1 原生关节目标 | 与上面的机械臂 RoboLab 是不同项目 |
| Digit / T13 | 原生身体和手臂关节动作 | 行走并跟踪双手目标，没有额外搬箱动作 |
| OmniIsaacGymEnvs / T14 | ANYmal 原生关节目标 | 原生 PD 产生力矩 |
| Flamingo / T15 | 原生腿部、其他位置关节及轮速通道 | 接口已写，初始化仍阻塞；腿部电机空间角度需考虑原齿比 |
| OmniDrones / T16、T17 | 各旋翼原始输入 | 分别为吊载悬停、托举倒立摆轨迹跟踪 |

### 无人机旋翼输入特别说明

`-1` 对应零稳态推力，`0` 对应一半最大稳态推力，`+1` 对应最大稳态推力。零输入不是悬停或停止指令；仍有原生电机滞后。各旋翼推力沿自身局部 +Z 方向，差动输入产生力矩；没有默认附加悬停或平衡控制器。

### 轮足输入特别说明

T07/T08 每侧三个输入依次控制虚拟腿角度、腿长、轮速：角度目标 `0.35u rad`，腿长目标 `clip(0.237+0.06u, 0.18, 0.30) m`，轮速目标 `24u rad/s`。零输入请求角度 0、腿长 0.237 m、轮速 0，不代表自动平衡。

## Bench2Dex / RobotWorld 41–49（2026-09-29新增）

提供 `observe`、`apply_action`、可关闭的 `coding_control`。观测是原生RGB相机与主动关节角；动作是双臂及Wuji灵巧手52个主动关节的绝对目标（弧度），并由原生mimic规则展开，不能当作关节增量或二值夹爪。普通动作单次1–50步，代码单次最多250步，控制20Hz、物理60Hz。代码回调每步读取关节角与时间；RGB在工具返回时交给模型，不是回调中的图像数组。环境和实测状态以[Bench2Dex说明](../third_party/benchmarks/bench2dex/README.md)及运行记录为准。
